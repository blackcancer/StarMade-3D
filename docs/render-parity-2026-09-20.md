## Corrections

### 1. Main light coordinates and per-draw updates

The native compatibility light is positional (`w=1`). Its world position is retained and
transformed by the current camera's world-to-view matrix, rather than normalized or
transformed as an entity-local direction. Repeated draws and multiple cameras always start
from the original world coordinates. Cube and LOD materials share this convention.

`sun.position` is the explicit API. The legacy `sun.direction` property is retained as an
unnormalized alias; a host must replace any previously normalized input with the actual
sector position. Preview values such as `(450,900,0)` are not a measured sector snapshot.
Shadow-camera directions remain a separate concept.

Uniform changes use `uniformsNeedUpdate`, not shader recompilation. A GPU regression draws
two objects with the same material but different per-object light states in one render;
the second object receives its own upload. LOD cloning retains the draw callback and detaches
nested light records/vectors that Three.js otherwise shares inside cloned uniform arrays.

### 2. Native lighting, shadow activation and fallbacks

The port no longer substitutes stronger, wider, host-colored spots for the native cube
shader's white coefficients: diffuse `1.2`, specular `0.3`, quadratic attenuation `0.02`.
The compatibility array again has eight slots, including the main light. Colored voxel
lighting remains in the vertex-light data; extra preview spots are not silently added on top.

The native shadow-path multiplier `1.2` is applied only when that path is enabled. A disabled
shadow pass is neutral, for both cubes and LOD models. This validates activation and gain,
not every spatial cascade, soft-shadow filter or native shadow-frame pixel.

Missing per-face light samples and unlit default segments no longer borrow another face's
light or invent RGB floors. Missing overlay maps are transparent instead of opaque white.
Neutral normal-map fallback alpha is zero, so missing normal assets do not mark surfaces as
emissive. These changes remove defects rather than compensating for them with exposure.

### 3. Normals, texture transport, alpha and timing

The CPU normal attribute now decodes the same effective normal mode as the packed GPU
attribute. Physical face normals still determine winding, avoiding a geometry change when
only the requested lighting normal changes. Shared half-block position calculations use one
axis-independent rule matching the native shader table.

The extra normal-map Y inversion was removed. Texture-array channels use the same raw
sampling convention as the corresponding native atlas path. Necessary GLSL ES type and
varying-name fixes remain; redundant matrix declarations were removed. Fractional-power
fade expressions explicitly clamp a negative base to prevent undefined GLSL results at
large distance. This clamp is a portability repair, not a claim that the native expression
was textually identical.

The arbitrary LOD alpha discard was removed; a one-level alpha sample now survives exactly
as the native fragment path prescribes. Animation advances on strict `time > 0.5`, consumes
one interval per update and retains accumulated delay, matching the reference Java updater.

### 4. Real LOD resources and static geometry

`mainConfig.xml` contains **95 active declarations**. The earlier regex also interpreted
**27 declarations inside XML comments**. The parser now excludes comments, and its output
is checked against browser DOMParser reading the actual installation file.

The low-level Ogre loader previously returned `SkinnedMesh` even for geometry without bone
weights. Native LOD bounds then failed while reading nonexistent skin attributes. Static
geometry now uses `Mesh`; geometry with bone assignments remains `SkinnedMesh`. Skeleton
integration fixtures now provide genuine weights instead of relying on the erroneous type.

All 95 actual LOD scene/model/material/texture chains now load, produce finite bounds and
render visible pixels with no missing-resource or shader errors. The runner reads 318 asset
files from the caller's installation and records their hashes. The accompanying contact
sheet uses **diagnostic lighting and a normalized framing per model**, not native gameplay
lighting or a common real-world scale. Files are transported in memory; native game assets
are not included in the delivered ZIP.

### 5. Preview settings

Both visual examples use an explicit unnormalized preview sun position. The forced `0.72`
LOD sun floor, `1.75` desk-light gain and other default extra-light compensations were removed
from the affected paths. Isanth's optional additional block spots require
`?experimentalBlockSpots=1`. These example changes were not presented as a newly executed
full Isanth/SDK scene; the standalone numerical and real-LOD browser fixtures were executed.

## Reproduction and acceptance still required

Run the commands in README. The executed groups are `build`, `typecheck:unit`,
`typecheck:browser`, `test:unit`, `test:tooling`, `coverage:check`, `test:render` and
`test:render:game` (the last needs `STARMADE_DIR`; the browser needs Chromium).
The coverage run rebuilds `dist`, inventories the output and requires a single complete
V8 collection. Its report is not assembled from separate runs to fill missing branches.

Before claiming native visual equivalence, compare paired native/renderer frames with the
same blueprint, block states, transformations, camera/FOV, viewport, sector sun, texture
pack, normal mapping, shadows, transparency, animation instant and post-processing settings.
Rails/attachment rotations, complete occlusion propagation, cascade filtering, bloom, gamma
and all scene combinations are not globally certified by the focused fixes in this report.
