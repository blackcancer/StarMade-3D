# Version 1.1.0 validation

This release adds demand-driven Decoder streams, bounded browser framing,
progressive Isanth rendering, shader/texture preparation and persistent blueprint
LOD sidecars. It preserves the existing native rendering, inspection and Display
APIs. Filesystem cache exports live in the separate `starmade-3d/node` entry.

Pinned references: StarMade-Open `e5a3b49d86943c4d618cea6512e28fa0b95901df`
and StarMade-Decoder 2.1.0 `e84ef38e757fb6ff1c56ffabf8c35205bfb200f2`.

All twelve release qualification recipes passed on 2026-09-24 with Node 22.16.0,
Three.js 0.164.1, installation-owned assets and Chromium software WebGL2.

The blocking CPU gate covers 12,293 emitted lines, 4,403 V8 branches and 896
functions. No runtime module was excluded and no threshold was reduced. GPU
assertions and the browser acceptance recipes are separate from CPU coverage;
they do not claim pixel-identical output to the StarMade client.

The release gate checks source fingerprints against the qualified inputs and
requires all twelve named recipes. Logs and receipts are stored under
`validation/v1.1.0/`; historical records remain unchanged. The qualification JSON
and artifact checksums accompany the GitHub release.

## Scope and limits

See [streaming](streaming.md) and [blueprint LOD](blueprint-lod.md) for ownership,
cancellation, companion directory naming, invalidation and rendering limits.
Blueprint LODs approximate occupied blocks with opaque cubes and averaged colors;
they retain docking transforms but omit propagated local lighting, shadow maps,
native model detail and Display text. Original SMD3 files remain authoritative.

Native copyrighted assets remain external. The npm-compatible tarball is
distributed through GitHub Releases, following the previous versions.
